# CT小舖御用機器人 V123

本版在 V110 開單 Interaction 修正基礎上，完成工單流程清理與同步修正。

- 移除舊版互動面板與舊版面板清理分支；Bot 啟動時只清理本 Bot 自己的舊互動元件。
- `/改名工單` 直接依服務、狀態、額度、數量改名，不再發舊版改名面板或第二層 Modal。
- `待倒` 僅保留為代肝改名狀態，不列入一般操作狀態。
- 結單統一寫入 `completed_at`；重新開放同步恢復權限、分類、名稱與訂單狀態。
- 開單防重複改以最新訂單狀態判斷，歷史結單工單不再阻擋新開單。
- 移除舊版排序別名、舊版名稱遷移指令與啟動時舊遷移流程。
- 保留必要的歷史頻道名稱辨識能力，避免舊工單失去可管理性。
- Slash Command 啟動同步仍以目前程式碼為準，移除的舊指令會隨 guild sync 清掉。
## V119 修正
- 修正結單／關閉工單時「找不到客人 ID」「頻道內沒有闆闆成員需要移除」、客人權限沒被拔掉的問題。
  - 原因：沒開 Server Members Intent 時，成員快取幾乎是空的；頻道對客人的權限覆寫會變成 `discord.Object`，舊程式只認 `Member` 而整個略過。
  - 改成直接讀頻道所有「會員個人覆寫」，用 `fetch_member` 向 Discord 取得成員，逐一拔除（客人與闆闆成員一起處理）。
  - 若對方身分組有 Administrator 權限，頻道權限無法限制他，回覆會明確標示。
  - 重新開放、自動辨識客人同步改用同一套邏輯。

## V116 修正
- 補回 V111「全面清理」誤刪、但仍被呼叫的 10 個函式（開單、結單、改名同步、自動分類、自動排序工單號都會用到）。
- `/改名工單`、`/修改狀態`、結單流程：改名加逾時，避免被 Discord 限速卡死。
- `/查詢工單` 分段送出、`/設定付款` 不再清空未填欄位、手動分流面板修正。
- V116：`/改名工單`、`/修改狀態` 改成結單時，一律嘗試拔除客人權限（找不到 buyer_id 也會自動尋找），並在回覆中顯示拔除結果與分類移動結果。
- V116：拔客人權限失敗為 Forbidden 時，回覆會提示需要「管理身分組」權限；啟動 log 增加 manage_roles 檢查。


## V117 新增
- 結單時自動移除頻道內擁有「闆闆」身分組的成員（客人權限照常移除）；重新開放時自動加回。
- 身分組名稱可在 bot.py 的 `BOSS_ROLE_NAME` / `BOSS_ROLE_ID` 調整。

## V118 修正
- `/改名工單` 改成兩個子指令：`/改名工單 幣號`、`/改名工單 代肝`，狀態與額度使用固定選項，選單立即顯示（不再等機器人 autocomplete 回應）。
  - 幣號：狀態 待付款／待交貨／待處理／結單；額度 50M／100M／200M；可填數量。
  - 代肝：狀態 待付款／待倒／待處理／結單；額度 50M／100M／150M／200M／300M／400M／500M…1000M。
- 修正「已收到付款明細」訊息會把 `\n` 當文字顯示、沒有換行的問題。

## V122 發號與分類排序
- `/自動排序工單號`：依頻道建立時間排序（最早 = 0001），完成後計數器重設為「現存工單數 + 1」，並清掉已刪除頻道的舊紀錄。
- 新開單發號改為「現存工單最大號 + 1」，已刪除頻道留下的舊號碼不再造成跳號。
- 新增 `/發號 查看`、`/發號 設定`、`/發號 同步`、`/發號 本頻道`。
- 開單時頻道建立失敗，會把剛配發的工單號退回，不再憑空跳號。
- `/自動排序工單號` 完成後，狀態頻道裡的「訂單 #xxxx」卡片會同步換成新工單號。
- 修正訂單狀態卡的鎖：原本因 sqlite3.Row 沒有 `.get`，所有訂單共用同一把鎖，改成每張訂單各自一把。

## V122 分類串（幣號工單、幣號工單1、2…）
- 以 `/設定開單分類` 設定的分類名稱為準，名稱相同、結尾數字不同的分類視為同一串，依數字由小到大排列。
- 新開單放進整串的最後一個分類；滿 50 個頻道就自動往下新建下一個（例如「幣號工單6」），權限沿用上一個分類。
- `/自動排序工單號` 除了重新編號，還會依工單號把工單排進整串分類：前 50 張在第一個、接著 50 張在下一個……，分類內也由小到大；不夠就自動新建分類。
- 開單流程加上鎖，同時多人開單不會把同一個分類塞爆。
- 結單分類（幣號結單／代肝結單）名稱不同，不會被搬動。
- 排序時不論工單原本在哪個分類（或沒有分類）都會整理進分類串；只有已在「幣號結單／代肝結單」固定分類內的結單工單不搬動。
- 排序時若各分類都已滿 50、互相卡住（例如兩個分類要對調），會先把還沒到位的工單搬去臨時的「整理中暫存」分類，再搬進正確分類，完成後自動刪除暫存分類；搬不出來的會保留暫存分類並計入失敗，不會讓頻道失去分類。
- `/自動排序工單號` 執行期間會暫停開單（共用開單鎖），避免新單撞號或被排進錯的分類。
- `/自動排序工單號` 每次都完整重排：已經排好的工單也會重新檢查編號，並把每個分類內重新由小到大排序，不會因為看起來已排好就跳過。
- 分類改為「依號碼區段」固定對應：幣號工單 = 0001–0050、幣號工單1 = 0051–0100、幣號工單2 = 0101–0150……（每段 50 張）；該段分類不存在就自動新建。
- 分類裡若有非工單頻道佔位子，放不下的（號碼較大的）會順延到下一個分類。
- 沒設定開單分類時，會從工單目前所在的分類名稱推斷整串分類，並自動設為開單分類。
- `/自動排序工單號` 新增選項「包含結單分類」：預設不搬已在結單分類的工單；選「是」會連它們一起搬進分類串。
- 完成訊息會列出每個分類實際放了哪一段號碼；搬移失敗時會顯示錯誤原因（例如缺少管理頻道權限）。
- 名稱含「服務中」的分類，裡面的工單在 `/自動排序工單號` 時完全不動：不改名、不換號、不搬分類（只有結單時才會被移動）；其他工單依建立時間編號，並跳過被它們佔用的號碼。完成訊息會顯示有幾單被略過。
- 分類排列改成「一次請求」把整批工單的所在分類與順序全部設好（不依賴頻道快取、不會卡在分類滿 50）；若 Discord 拒絕才退回逐張搬移（含暫存分類機制）。完成訊息會顯示用了哪種方式，以及偵測到哪些分類。
- 搬移逾時從 20 秒放寬到 90 秒，避免被 Discord 限速時誤判失敗；排序太久導致互動過期時，結果會改發到目前頻道。
- V123：`closed-0053`、`archived-0012` 這類舊格式的結單頻道，即使資料庫沒有紀錄也會被辨識為工單，納入編號與分類排序（`closed-announcements` 這種沒有號碼的不會被誤認）。
